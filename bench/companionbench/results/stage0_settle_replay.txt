SETTLE UNIFICATION -- STAGE 0 (SECOND COLLECTION)

VERDICT: THIS EVIDENCE CANNOT DECIDE IT. The population excludes the at-risk stratum, and the
interval contains the effect the plan was written about. Do not proceed to the implementation
stages -- not because the benefit was shown to be absent, but because there is not yet a
sample that could tell absence from a failure to look.

  The distinction matters when this is read back. "Not reproduced" is not "refuted". The 95%
  upper bound is 0.250, so this sample does not separate 0% from the plan's 7%: that figure
  sits comfortably inside the interval. And the turns most at risk of an early accept are the
  ones with PAUSES -- a tool call, a retrieval, a long think -- of which this population
  contains none. So the state is not "7% is false"; it is "the stratum where 7% could live
  was not measured".

  The one genuine early accept found anywhere came from the marker table rather than the
  predicate. That is a fix, not an acquittal: it says nothing about whether the predicate
  itself truncates on turns this collection did not contain.

-- the collection ----------------------------------------------------------------

  120 turns, 12 prompts x 10 cycles, driven through the real wait_for_idle on a live
  tenant, recorded into this campaign's own file. Zero probe contamination.

  Label tail: 15 polls, about 8 seconds past acceptance -- comfortably beyond the dwell
  production itself requires. The first collection used 4 polls (~2s) and every one of its
  127 tails was exactly 4 long with no change, which left the result unreadable: a zero
  could have meant the predicate was fine or that nobody looked long enough.

-- the result --------------------------------------------------------------------

  TURNS WHOSE TEXT CHANGED AFTER PRODUCTION ACCEPTED: 0 of 120, at 8 seconds.

  That is a direct observation of the phenomenon, not an inference from a rate. Production
  accepted, and the answer then sat unchanged for eight seconds, on every turn.

settle replay: 120 turns
  legacy   accepted  120  never   0  truncated    0  rate 0.000
  sampled  accepted  120  never   0  truncated    0  rate 0.000
  reduction:  0 of 120 turns no longer truncated  =  0.000  95% CI [0.000, 0.250]
              interval method: cluster bootstrap over 12 prompt(s)
  discordant: legacy worse 0 / sampled worse 0
  (sampled_worse is structurally zero: the sampled predicate is the legacy one plus a floor, so it cannot accept earlier. This is not evidence -- it is the definition.)

  THE INTERVAL IS NOT A BOOTSTRAP AND NOT THE SAME ESTIMAND AS THE POINT FIGURE. With no
  events observed, a nonparametric bootstrap returns [0, 0] -- it cannot invent an event it
  never saw -- so the bound is the rule of three over the twelve prompts: 0.250, against the
  0.030 a turn-level Wilson would print. But the point estimate is a TURN-level proportion
  while that bound treats a PROMPT as the unit, so read 0.250 as a conservative sensitivity
  bound rather than a calibrated interval for the same quantity. It was labelled "cluster
  bootstrap", which was a correct number under the name of a different method.

  And that twelve prompts are twelve INDEPENDENT units is an assumption. Cycling twelve
  convenience prompts through one tenant does not establish it; it is simply less wrong than
  treating 120 correlated turns as 120.

-- what this does and does not settle ---------------------------------------------

  SETTLED: on THIS population the sampled predicate has nothing to fix -- its sample floor
  never changed an acceptance to a different text -- and the label is now real, which the
  first collection's could not be shown to be.

  NOT SETTLED: whether the plan's ~7% is wrong. With an upper bound of 0.250 this sample
  cannot separate 0% from 7%. Absence of evidence, at this sample size, over this stratum.

  NOT SETTLED, and this is the limit that matters: the prompts are ordinary chat questions.
  They stream steadily. The turns most at risk of an early accept are the ones with PAUSES
  -- a tool call, a retrieval, a long think -- and this population does not contain them.
  A convenience sample of one tenant on one night may therefore exclude precisely the turns
  the plan was written about. Reproducing it with agent/tool turns is the collection that
  would close this, and it is not the same run.

-- what WAS found ----------------------------------------------------------------

  In the first collection, one genuine early accept: on a throttled request Copilot showed
  a 'still organising the information' placeholder and production accepted it as the
  answer, because that string was not in PROCESSING_MARKERS. No sample floor prevents that
  -- a placeholder is perfectly stable for as many samples as you require. It is now a
  marker. The defect was in the marker table, not in the predicate the plan proposes to
  replace.
