# セキュリティモデル

このツールの認証・認可の仕組みと注意点をまとめます。全体像は [README](../README.md) を先に読んでください。

---

## まず前提 — これは誰のための道具か

これは **あなたが自分で所有・管理するマシン** で、**あなたが既にアクセス権を持っているデータ** に対して、**あなた個人の用途** で動かすツールです。SaaS でもホスティングサービスでもなく、サポート契約もありません。`m365-` で始まる名前ですが Microsoft 製ではありません。

以下のいずれか 1 つでも当てはまる組織なら、**会社のノート PC には絶対にデプロイしないでください**:

- 個人用 MCP サーバーの稼働が禁止されている
- Microsoft Dev Tunnels が承認されていない
- Copilot Studio のエージェントは IT 管理のテンプレートからしか作れない
- 任意の Python パッケージを会社 PC に入れることが禁止されている
- AI のツール実行・エージェントのファイルアクセス・サードパーティ GitHub クローンを「セキュリティインシデント」と扱う運用がある

ライセンスは **MIT**。**無保証・無責任・無サポート**。運用上の事故に作者は一切責任を負いません。特に `MCP_UNLOCK_PASSWORD` の取り扱いには細心の注意を。「禁止されていない」≠「許可されている」を取り違えないこと。運用は必ず**明示的に承認を取る**のを原則にしてください。

## 3 層の重ね

順に通過しないと先に進めません:

| 層 | 仕組み | 失敗時 |
|---|---|---|
| **認証** | 固定 Bearer トークン（`MCP_API_KEY`、40 桁のランダム hex） | 401 Unauthorized |
| **場所の認可** | 全ファイルアクセスは `_validate_path` を通過。`MCP_ALLOWED_BASE` 配下以外はブロック | `PermissionError` |
| **行為の認可** | 書込 / 実行系は `require_unlocked()` を呼ぶ。`X-Forwarded-For` か socket peer から取った IP をホワイトリストと突き合わせ（TTL あり） | "locked" メッセージで `unlock(password)` を要求 |

## 知っておくべきこと

- unlock パスワードは API キーとは **別物**。`unlock()` は成功時に **unlock_token** を1度だけ返し、
  サーバはそのハッシュのみを保持します。変更系・実行系は `call_tool(..., unlock_token=...)` で
  これを提示します。
- **既定ではトークンの提示は必須ではありません**（`MCP_REQUIRE_UNLOCK_TOKEN=1` で必須化）。
  必須化前は、解錠済みの識別子だけで変更系が通ります。この識別子は転送ヘッダ由来で、
  呼び出し側が申告する値です。したがって **必須化するまでは「片方の鍵だけでは通らない」とは
  言えません**。以前この文書と README はそう書いていましたが、事実と異なりました。
  トークン無しで通った回数は `.fleet/unlock_token_gap.json` に記録されるので、
  これが増えなくなった時点で必須化してください。
- `127.0.0.1` / `::1` は自動的に信頼（ローカル開発用）。
- ODBC は `readonly=True` で接続し、`SELECT / WITH / EXEC / SHOW / DESCRIBE` のみ許可。
- DB 認証は Windows / Entra 統合認証なので、エージェントは **あなたの既存権限の範囲でしか SQL を投げられません**。DBA への新規アカウント申請は不要。
- Bearer キーのローテーションは `.env` 編集 → 再起動だけ（`rotate_secrets.bat`）。古いキーは即死。
- unlock した IP は `MCP_UNLOCK_TTL_DAYS` 日間（既定 30 日）解錠されます。Copilot Studio バックエンド経由だと送信元 IP が変わることがあり、その都度 `unlock` を要求されますが、これは正常動作です。

## トンネルの匿名アクセスについて

devtunnel は `--allow-anonymous` で公開します。それでも安全な理由は、サーバーが **Bearer API キー（`MCP_API_KEY`）** で認証しているためです。URL を当てずっぽうで叩いた人・bot は即 401 になります。トンネル名と公開 URL は人ごとに違い、`.env`（git 管理外）に記録され共有・コミットされません。

## シェル実行があるとき、この3層は何を守るのか

`shell_exec` / `run_python` は **同一 OS ユーザーの権限で任意コードを実行**します
(`tools/code_exec.py` の docstring に "NOT a sandbox" と書いてあるとおりです)。
この2つが使える状態では:

- **`_validate_path` は境界ではありません。** ファイル系ツールから `.env` と
  `.companion_gates` を返さないようにしてありますが、サブプロセスからは `open('.env')` で読めます
- **承認ゲートは「人間向けの安全インターロック」であって、悪意あるコードに対する境界ではありません。**
  ワーカーは承認ファイルを直接書けます
- **ファイルの ACL も助けになりません。** そのファイルの所有者はワーカー自身です

これは欠陥ではなく、**この道具が何のためにあるか**の帰結です。守っている相手は
**「有能なエージェントが誤って破壊的なことをする」**であって、既に乗っ取った攻撃者ではありません。
その前提での防御は3段です:

| 段 | 役割 | 限界 |
|---|---|---|
| **決定論的な網** | `destructive_shell()` が名指しした操作は**確実に**捕まえる。`pytest` や `git status` では鳴らない（鳴る網は無視される網になる） | 難読化や、パターンを持たない破壊操作は見えない |
| **モデルの判断** | 網が構造的に見られないもの（新しい形、意図、その場の文脈で初めて破壊的になるもの）を読む | 判断なので誤る。網が確実に扱う操作をここに任せてはいけない |
| **人の承認** | 前2段が止めたものも、明示的に承認すれば実行される。**その判断と責任は利用者のもの** | 逃げ道の無いゲートは丸ごと切られる。逃げ道があるから厳しくできる |

「確実に捕まえる」から「判断に任せる」へ移すのは**保証の変更**です。正規表現を編集した副作用として
起きてはならず、意図した判断として記録してください。

**`isolated` と名乗ってよいのは、OS が強制する境界を実際に有効化し検証したときだけです。**
本プロジェクトはそれを提供しません。管理者権限・WSL・SSH 先・sandbox の導入を
利用者に求めないという前提で作られているためです。署名付きゲート・HMAC・名前付きパイプ・
localhost エンドポイント・プロセス内秘密は、いずれも**ワーカーが鍵を得られず経路を呼べない場合にのみ**
機能します。同一ユーザーの任意実行がある限り、その前提は成立しません。

## これは「何ではないか」

- ハードン済みのマルチテナントサービスではない
- ペネトレーションテスト済みではない
- あなたの PC を既に乗っ取った攻撃者からは何も守れない（その攻撃者は既にエージェントと同等以上の権限を持っている）
- 同僚に unlock パスワードを教えてしまうあなた自身からは守れない。**教えないでください**

---

## データはどこに流れるか

M365 Copilot のチャット内容と、エージェントが返した文字列は Microsoft の Copilot Studio に流れます。エージェントを Copilot Studio で動かす以上、避けようがありません。ローカルファイルの中身も、エージェントが回答に含めればそのままチャットに出ます。**取り扱い注意の情報は最初からエージェントに見せないこと**。`MCP_ALLOWED_BASE` を限定するのは、この事故を物理的に減らすための仕切りです。`render_diagram`（Kroki）や `web_fetch` は外部にデータを出すので、社外秘では使わないこと。

監査で **バレます**。隠す前提で運用しないでください。devtunnel のログは Microsoft に残り、Copilot Studio の操作履歴も残ります。最初から「会社の AI 活用の試行として、自分の PC で動かしている」と説明できる形で運用してください。

## 退職・PC 返却時の掃除

`.env` の API キーと unlock パスワードは破棄。Dev Tunnel と Copilot Studio エージェントは削除。`.unlock_state.json` `.memory_state.json` `.todo_state.json` `agent_memory/` 配下も削除。PC 返却時にこの掃除は必須です。
