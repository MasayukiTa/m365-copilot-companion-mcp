# Claude-Code friction inventory — cockpit (FleetCockpit.cs) + companion chat (CopilotChat.cs)

This turns the user's "言葉にできないほど差が大きい … 私が使うときに戸惑う場面がある" into a concrete,
code-anchored list. The features exist; the friction is in **how a Claude-Code user reads, acts, and
gets feedback**. CC's mental model is: one linear thread, every action either a slash-command in ONE
input or an inline affordance with an obvious label, every click gives immediate textual feedback,
and there is exactly one place to look for "what is happening now." This UI instead spreads state
across a header subtitle, toolbar, cards, banners, a separate window, and silent file writes — so the
user constantly has to *hunt* for the control and *guess* whether their click registered. Every item
below cites the exact handler/line and a concrete fix, ranked by how often a daily user hits it.

Legend for **Maps to**: (a) sub-agent visibility · (b) single expandable thread · (c) slash+steering
· (d) plan/TODO · (x) general operability.

## Top themes (for the implementer)

1. **The whole-card click target (#1) is the root of a cluster** — it forced SwallowMouseUp, the
   chevron's PreviewMouseDown hack, and `e.Handled` in every inner row. Removing it and making
   "open" an explicit affordance simplifies the card and removes the user's central hesitation.
2. **Hidden-until-hover / hidden-until-expand (#2,#3,#8,#17)** is the dominant discoverability
   failure: steering, slash commands, rename, delete, and per-card detail are all invisible by
   default. CC's bias is the opposite — affordances are visible and labeled. A single sweep making
   these persistent/labeled closes most of the "戸惑う" gap.
3. **Silent, delayed, state-dependent feedback (#5,#12,#14,#15)** — clicks write JSON files and the
   effect appears elsewhere ~1 tick later with no acknowledgement, and the SAME gesture behaves
   differently based on invisible live/stale/autoscale state. Add optimistic in-place feedback and
   make the branching visible.
4. **Two windows + invisible sub-agents (#4,#10)** is the structural gap vs CC's single thread; it's
   the (a)/(b) workstream and the biggest lift, but #1–#9 are cheap, high-frequency wins to do first.
