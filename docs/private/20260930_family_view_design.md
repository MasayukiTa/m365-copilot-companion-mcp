# Owner-facing prompt and family view for the Fleet Cockpit (design)

Date: 2026-09-30. Status: design only, no product code changed. Author: Claude.
Follows the internal maturity roadmap (private). Code read: `origin/main` at 76e0bdb (worktree); the live checkout (other branch, uncommitted edits) was read for the same symbols and matches within a few lines (`_task_anchor` 3892, `user()` 1747, `fanout_family_view` fanout.py:754, `_final_worker_entry` fleet_runner.py:4421). Line numbers below are origin/main.
Legend: [V] verified by reading code or measuring files; [A] assumption to check before the PR that relies on it.

Goal: the owner must be able to see (a) exactly what each worker was first given and whether later prompts still carry it, (b) what the other members of a fan-out family are doing, (c) whether a worker was interrupted rather than cancelled. Read-only, human-facing, no model involvement: everything is a deterministic function of files the coordinator already writes.

## 1. What exists today, and what is missing

### (a) First prompt and goal drift
- Composition [V]: `RelayWorker.__init__` builds `composed_goal = _with_repo_contract(_with_theme_memory(_with_matched_skill(goal)))` (relay_fleet.py:3144-3146; contract prefix `_CONTRACT_HEADER` :7419, `_with_repo_contract` :7716, `_with_theme_memory` :7654, `_with_matched_skill` :7501), then `_initial_job_with_unlock` -> `opening_turn(goal, PROTOCOL)` (:1380, planner.py:162). Turn 1 = `conversation_start_label + PROTOCOL + [contract + memory + procedure] + goal` (:3241 for the fan-out variant that appends `SPLIT_JOB`). The body ENDS with the bare goal by construction (suffix invariant used by `_composed_prefix`, :3160).
- Recording [V]: `_Transcript.user()` (relay_fleet.py:1747) writes the full sent prompt, redacted by `_redact_unlock_password` (:1418, fails closed to a marker), one JSON line per turn `{turn, role, text, ts}`; the first line is `{"meta":true,"key","name","goal","ts"}` with the untruncated goal (:1707). Called from `_send` at :4108. A fresh replay opens a NEW file `<key>_a<n>` (:3416); `worker.attempt_transcripts` lists them (fleet_runner.py:1698).
- Later prompts [V]: continuation nudges go through `_task_anchor` (relay_fleet.py:3892), which prepends only the FIRST NON-EMPTY LINE of the goal cut at 160 chars plus cwd; 21 call sites (4246 ... 6062). Replay (:3725) and recycle (:3820) re-send the full composed goal; a steer sends `【ユーザーからの追加指示】` + text and no goal.
- Measured on the live `.fleet/transcripts` (2124 files, 2096 already gzipped by retention): over 313 transcripts, first prompt contains the meta goal verbatim in 313/313 (size 1.9k-3.9k chars in the 28 plain files, median 2.7k). Of 1102 later user prompts, 361 (33%) carry the whole goal, 488 (44%) carry only the `修正中です` 160-char anchor, 253 (23%) neither (steers, recovery, review jobs). So "the continuation no longer contains the goal" is the normal state, not an edge case.
- Surfaced to the owner today [V]: nothing per-prompt. status.json worker rows carry `goal` (full), `goal_summary`, `transcript`, `attempt_transcripts`, `run_id` (fleet_runner.py:1644-1698) but no hash, length, or first-prompt pointer. The cockpit Conversation tab (`TabConversation` FleetCockpit.cs:14320, `MiniThread` :14423, `ReadLastTurns` :14557) shows only the last turns; nothing shows the composed first prompt. The cockpit has no gzip reader (grep `GZipStream`: none), yet almost all transcripts are `.jsonl.gz`.
- Missing: first-prompt ref (path, turn, sha1, chars), per-prompt goal coverage, drift flag, UI to open the first prompt and to mark drifted prompts.

### (b) Family view
- Data on hand [V]: `campaigns.jsonl` (written relay_fleet.py:8120-8141): header `{kind:"campaign",campaign_id,goal,n,cwd,checks,partial}`, child lines `{campaign_id,task_id,subtask_index,text<=4000}`, `{kind:"merged"}` written when the merge is QUEUED (`_note_merged` :7986). Read by `campaigns_from_ledger` (fanout.py:479). Child text is built by `child_goals` (fanout.py:365): parent goal + `【この会話が担当する範囲 — 全体の i/N】` + step + `上の範囲だけを担当してください...` + closing instruction. status.json worker rows carry `campaign_id, task_id, parent_task_id, role (subtask|aggregator), depth, subtask_index` (fleet_runner.py:1685-1690) and a derived `fanout` marker (`fanout_family_view`, fanout.py:754; attached at fleet_runner.py:1709-1713 and 4489) with `kind`, `children_total/done`, `missing_slices`, `fanin_state` (pending|ready|merging|merged).
- Gaps [V]: (1) FleetCockpit.cs never reads `fanout`, `campaign_id`, `role`, `subtask_index` or `parent_task_id` (grep: the only `fanout` hits are the `/fanout` setting), so the family structure is computed and dropped. (2) `_final_worker_entry` (fleet_runner.py:4421-4472) copies task_id/parent/campaign/role/depth but NOT `subtask_index`, so in the frozen final status a child's marker degrades to "subtask" without a number. (3) history.json rows (keys: conv_title, goal, jid, key, name, outcome, phase_events, run_id, status, transcript, turn, ...) carry no campaign/role, so an archived family cannot be rebuilt from history.json; only `campaigns.jsonl` plus transcripts survive. (4) No per-child artifacts in Python: `execution.artifacts` exists only for the local-loop store (local_job_store.py:1063); for Copilot workers the cockpit regex-detects paths in the result text (`DetectExistingPaths` FleetCockpit.cs:13885, `ArtifactsRow` :13978). (5) `last` is 600 chars (fleet_runner.py:1666). (6) No structured "scope" exists beyond the step prose, and no per-child edit record: children share one cwd, so a git diff cannot attribute edits to a child [V by `child_goals` passing the parent cwd].
- The parent is `done/FANOUT` from turn 1 on purpose (interrupted-resume design, section 5); its true state comes from the family fields.

### (c) Interrupted vs cancelled
- Today [V from the interrupted-resume design, `docs/private/20260930_fleet_interrupted_resume_design.md`]: the reaper writes `cancelled` for a coordinator death. That design (not yet implemented; PR is design-only) adds worker `status="interrupted"`, `outcome="INTERRUPTED"`, `resumable`, status.json `interrupted{...}`, and a parent `display_state` in {awaiting_children, merging, done, merge_failed, interrupted} with `children_done/children_total`, plus the `merge_done` campaign line and `.fleet/interrupted/<run_id>.json`. Cockpit label/pill additions are listed there (StatusLabel :1712, Theme.cs status/timeline maps). Missing here: the family panel must consume those fields; until the reaper change lands the view shows exactly what status.json says (`cancelled` stays `cancelled`; a healthy child wrongly reaped cannot be told apart deterministically, so no guess is made).

## 2. Data contract (additive; only refs and small scalars, never prompt text)

New pure module `relay/family_view.py` (no I/O except two optional readers; no imports from relay_fleet; unit-testable without a browser). The coordinator calls only the cheap part.

Per worker row, added by `_snapshot` (fleet_runner.py:1644) and `_final_worker_entry` (:4421):
- `first_prompt`: `{"path": <transcript of attempt 0>, "turn": 1, "sha1": "<40 hex of the redacted text as stored>", "chars": n, "goal_chars": g}`. Hash of the redacted text, so the owner can verify it against the file.
- `latest_prompt`: `{"turn": t, "sha1", "chars", "kind": "first|continuation|steer|recovery|replay|recycle", "goal_state": "full|partial|absent", "goal_covered": k, "goal_chars": g}`.
- `prompt_goal_intact`: bool = `latest_prompt.goal_state == "full"`. `prompt_drift_turns`: count of prompts whose goal_state was not full since the last full one, capped.
- Family fields (all rows, from `campaign_id`/`role`): `family_role` (`parent|child|merge|solo`, mapping of the existing `fanout.kind`), `scope` (`"i/N"`, N from the campaign header `n`, else from the parent marker), `campaign_id` (already there).
- Parent/merge row only: `family_members`: list of child names (cap 12 = `MAX_CHILDREN`, fanout.py:47); `family`: `{"children_total","children_done","merge_state","merge_worker","display_state","warnings":[{"child","other","path"}]}` (warnings cap 10). `display_state` and `interrupted` come from the interrupted-resume design; this module only copies them.
- Plus the one-line bug fix: `_final_worker_entry` gains `subtask_index`.

Where computed:
- `describe_prompt(text, goal)` (pure, O(len)): sha1 + chars + goal coverage = length of the longest prefix of `goal` occurring in `text` (locate `goal[:32]`, extend by comparison; `full` iff covered == len(goal); `partial` iff covered >= 32; else `absent`). Kind is decided by the same literal prefixes the worker already writes (steer wrapper, `SYSTEM_RECOVERY_PREFIX`, `RECYCLE_PREFIX`, `conversation_start_label` `-replay`/`-recycle`), never by a model. Called from `_Transcript.user()` right after redaction (one extra sha1 of a few KB per turn; measured prompt size 2-4k). The transcript object keeps only `first` and `latest` descriptors (2 small dicts); `_snapshot` copies them. The coordinator does no file reading for this.
- `family_rows(workers, ledger_headers)` (pure): extends `fanout_family_view` (call it, do not fork it), adds scope/members/warnings. Called from the two places that already call `fanout_family_view` (fleet_runner.py:1711, 4489). `ledger_headers` = `{campaign_id: n}` read from `campaigns.jsonl` through a `(mtime,size)`-cached reader so the 988-line ledger is not re-parsed each 1 s tick; failure returns `{}` and the view degrades to marker-only.
- `read_first_prompt(path)`: tolerant reader (plain, then `.gz`; first `user` line) used by tests, the `fleet_diag` CLI and, mirrored in C#, by the UI. Never used by the coordinator.
- Scope-overlap warning, only in this deterministic form: for each child, `step` = text between the `【この会話が担当する範囲 — 全体の i/N】` header and the `上の範囲だけを` trailer (format owned by `child_goals`; unparseable -> no warning); `declared(B)` = path-like tokens (absolute Windows paths, or relative tokens with a file extension) in `step(B)` minus those in the parent goal; `claimed(A)` = path-like tokens in A's final result text / `last`. Warn `A touches B's scope` iff a token of `claimed(A)` equals or lies under a token of `declared(B)` and is not in `declared(A)`. It says "claimed": the source is the child's own reply, there is no structured record of what it wrote [V], and semantic scopes (months, date ranges, sections, "the first half") have no deterministic overlap test, so those are NOT warned about. If the incident's overlap was semantic, this feature will not catch it (open question 3). Ships last and optional.
- Cost/size: 2 small dicts per worker (~250 B) + family block on one row; 30 workers ~ 8 KB on a status.json that is 4.8 KB for one worker today [V]. No prompt text, no goal text beyond the existing `goal`.

## 3. UI spec (extend STAB-002, do not fork it)

STAB-002 is CLOSED and on main: the left 220 px Spine is `内容詳細` (`BuildSpineContent`, FleetCockpit.cs:5191, following `SpineFocusWorker` :4996, repaint key `SpineDetailSignature` :5018) with the timeline beneath (`AddSpineTimeline`); the expanded card keeps the timeline and the full Goal in Overview (`TabOverview` :14113). The other engineer edits this region. Rules:
- Put NO new rendering logic in FleetCockpit.cs. New WPF-free static class `ui/FamilyView.cs` (same pattern as `SubmittedTasks.cs`, `FleetConvIdentity.cs`) owns parsing status rows into a `FamilyModel`/`PromptModel` and all wording/decisions; FleetCockpit.cs gets only small call sites.
- Left Spine (same focused worker): under the existing status line add ONE compact line "指示: 先頭 2.7k字 sha 3f9a1c · 最新 継続 · 目標 160/550字のみ" (drift amber) and, when the focused worker is in a family, a "ファミリー / Family" block after Waiting/note and before the timeline: role + scope ("子 2/4"), then one row per member (name, scope, status pill, `outcome`, turn, last progress line truncated to 60 chars), merge state row, warnings. Cap 12 rows; more shows "+n". Add the new fields to `SpineDetailSignature` so it repaints when they change.
- Expanded card: a 5th tab "指示 / Prompt" next to Overview/Conversation/Review/Logs (`BuildCardTabs` :13765): shows first prompt metadata (path, turn, sha1, chars), a read-only, scrollable, monospaced view of the first prompt read from the ref (plain or `.gz` via the static class, cap 64 KB read, then "truncated, open file"), a small table of every user prompt (turn, kind, chars, sha1 short, goal_state) built by one streaming pass with a per-file cache keyed by (path, length, mtime), and "Open transcript". Family block also appears in Overview for parent/merge rows with full detail.
- Labels (Theme.cs, alongside `StatusLabel`/`TimelineLabel` :260/:299): ja/en `指示`/`Prompt`, `初回プロンプト`/`First prompt`, `ファミリー`/`Family`, `子`/`Child`, `統合`/`Merge`, `目標の一部のみ`/`Goal partly carried`, `目標なし（継続）`/`No goal in this prompt`, `中断`/`Interrupted` (already added by the interrupted design), `他の子の範囲に触れた可能性`/`May touch another child's scope`. Colors: warning for partial, faint for absent, existing Info/Success for status.
- Drift flag semantics: raised (amber) when the LATEST prompt has `goal_state=="partial"` (a truncated restatement, the misleading case); shown neutral-grey "no goal in this prompt" when `absent` and kind is continuation/steer/recovery; never raised for `full`. It states facts (covered/total chars), not a verdict: a same-conversation continuation legitimately need not repeat the goal (open question 1). The flag is set on the worker if any prompt in the run was partial (`prompt_drift_turns > 0`), with the list in the Prompt tab.
- Empty/error states: no `first_prompt` (old status file, worker not started): "(初回プロンプトはまだありません)"; transcript unreadable, missing, or hash mismatch with the row: show the row facts and "file not readable / changed since"; `.gz` missing both forms: same. Old snapshot without family fields: block hidden, nothing fabricated. Solo worker: no family block.
- Redaction: the UI only reads the already-redacted transcript (same file the Conversation tab reads). If the redaction marker is present it is shown as is. The UI never re-reads `.env`/settings and never displays status.json `goal` under the Prompt tab as if it were the sent prompt.
- Performance for 30+ workers: the Spine and Prompt tab build for ONE worker only; family block reads only status.json rows already in memory; transcript reads happen only when a Prompt tab is opened or the focused worker's `first_prompt.sha1` changed, on the UI thread with a byte cap, cached; nothing per card in the list except the existing pill. No new timers.

## 6. Measured vs assumed; open questions

Measured [V]: composition order and suffix invariant; transcript line format; 313 sampled transcripts (28 plain + 285 gzipped, newest first): first prompt contains the goal in all, later prompts 33% full / 44% anchor-only / 23% neither; 2096 of 2124 files gzipped and the UI has no gzip reader; the cockpit does not read `fanout`/`campaign_id`; `_final_worker_entry` lacks `subtask_index`; history.json has no family keys; status.json is 4.8 KB with one worker; campaigns.jsonl schema; `MAX_CHILDREN` 12.
Assumed [A]: `_Transcript.user()` runs on the coordinator thread so a sha1 there is negligible (needs a micro-benchmark in PR 2); csc can compile a `GZipStream` reader without extra references (System.IO.Compression is in the .NET 4 GAC, check the `Build` reference list); retention's `.gz` naming is exactly `<key>.jsonl.gz` for all files (seen for the sampled ones); the status `transcript` for a replayed worker points at the latest attempt so `first_prompt.path` must come from `attempt_transcripts[0]`.
Open questions for the owner:
1. Should a continuation prompt in the same conversation be expected to restate the goal? Today 44% restate only 160 chars. The flag reports facts; whether "absent" is a defect (and whether `_task_anchor` should carry the whole goal) is a separate product decision this view only informs.
2. Is the first prompt (which includes the shared contract and memory pointer) fine to show in full, given it can contain memory/skill text? Redaction is only the existing secret redaction.
3. What was the incident's overlap: shared file paths or semantic slices? Only path overlap can be warned deterministically.
4. Should archived families (history) be reconstructable? That needs `campaign_id`/`role` added to history rows (small change in the archive writer, not in this design).
5. Interrupted vs cancelled before the reaper fix lands: show as-is (this design), or add a heuristic? Recommended: as-is, no guessing.
