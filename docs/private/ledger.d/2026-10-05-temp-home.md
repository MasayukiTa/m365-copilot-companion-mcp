## 2026-10-05 - One swept temp home (%TEMP%\m365-companion)

- Change: nothing swept %TEMP%, so job logs, pasted images, bench scratch, agents' venvs and
  stray `playwright-artifacts-*` directories piled up until the disk was tight. New
  `relay/temp_home.py` (`temp_home()`, `temp_dir(name)`) names ONE directory,
  `%TEMP%\m365-companion\`, and `relay/fleet_retention.sweep_temp_home()` (called by `apply()`, so it
  appears in the existing retention report as the `temp_home` rule) removes entries there with
  no write for 24 h (`MCP_TEMP_HOME_MAX_AGE_H`).
- Writers moved: `tools/jobs.py` (job logs and the run_python script, under `jobs\`), bench
  scratch (`bench/companionbench/*`, `bench/swe_check_remote.py`, `bench/remote_grade.py`) via
  `dir=temp_home()`, and the pasted-image file of `ui/CopilotChat.cs` (`ChatTempHome.Dir()` in the
  WPF-free `ui/ChatSend.cs`). `scripts/supervisor.ps1` keeps its log where it was but rotates it
  at 5 MB to `.1` (one generation).
- Sweep safety: only the home, plus exactly `%TEMP%\playwright-artifacts-*` directories that are
  EMPTY and over 6 h old and `%TEMP%\copilot_paste_<8 hex>.png` over the age limit. Links and
  junctions are removed as links and never followed; a linked home is not swept; a locked file
  is skipped; the rule never raises. conftest redirects `relay.temp_home.system_temp()` so tests
  never see the real %TEMP%.
- Convention for agents and tools: venvs, clones and test scratch go under
  `%TEMP%\m365-companion\agents\<name>\` so the same sweep covers them. Written into AGENTS.md.
  A directory is judged by its newest file: a venv in use but not written for 24 h is swept.
- Not swept on purpose: the legacy `%TEMP%\m365-copilot-companion-mcp-jobs\` logs, the
  supervisor log's `.1` generation, anything else in %TEMP% (other programs', Edge/Playwright
  profiles, `uv`/`pip` caches), and the `playwright-artifacts-*` directories that are not empty.
- Tests: `relay/test_temp_home.py`, `scripts/test_supervisor_rotates_its_log.py`.
