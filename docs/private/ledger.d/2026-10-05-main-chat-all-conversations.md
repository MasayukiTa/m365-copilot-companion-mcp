## 2026-10-05 - Main chat lists every conversation on disk

- Change: old conversations could not be opened from the main chat (ui/CopilotChat.cs). Three silent limits, now removed.
  (1) The sidebar listed only the newest 80 transcripts, scanned once at startup; 3,309 were on disk. It now indexes the whole transcript directory by name and mtime (no file opened) and pages it: the newest 80 at startup, then an "older..." row that loads one local day per click (capped at 300 rows a page). The page logic is ConvListing in ui/FleetConvIdentity.cs (WPF-free, run by a compiled harness). Sub-agent transcripts stay hidden; opening a row still reads the local transcript first; the full goal is restored from the transcript's first line on open. The sidebar has no search box, so there was nothing to widen.
  (2) .fleet/conversations.json passed 2,097,152 characters, JavaScriptSerializer's default MaxJsonLength; the read threw, a bare catch returned an empty list, and no registry row appeared. Every JavaScriptSerializer in ui/*.cs now sets MaxJsonLength = int.MaxValue; ReadConvsRegistry and the other list readers log to .fleet/chat_listing.log and the sidebar shows a one-line notice (ja/en) instead of an empty list. RegisterConv/UnregisterConvs no longer write back after a failed read (that would have replaced the file with one row).
  (3) relay/fleet_retention.conversations dropped a row 24 h after nothing linked it, while its transcript still existed. A row is now dropped only when unlinked AND past the keep window AND its transcript (plain or .gz, any lineage segment) is gone. The registry is kept small by cutting `goal` of idle rows (transcript untouched for 1 h) to 240 characters with `goal_cut: true`; the full goal comes back from the transcript on open and from a live worker (relay/fleet_runner.merge_conv_rows). The first rewrite backs the previous file up as conversations.json.bak, once; writes are atomic.
- Behaviour: with fewer than 80 transcripts the list is unchanged. On a COPY of the live registry: 3,355,554 bytes (1,143 rows) -> 868,319 bytes (about 760 KB per 1,000 rows).
- Tests: ui/test_the_conversation_list_shows_every_transcript.py, relay/test_conversation_registry_keeps_listable_rows.py (both in ci.yml); source-shape check that no list reader has a swallowing catch.
- Open: the sqlite `sessions` table is retention-pruned at 90 days (558 rows). It is not touched here. It should probably be extended or switched off: the transcripts and fleet_turns already outlive it, so a session row older than 90 days is the only part of an old conversation that disappears. Decision for the owner. The one-time migration runs inside the existing retention pass (each coordinator start), not at chat start.
