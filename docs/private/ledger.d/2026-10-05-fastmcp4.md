## 2026-10-05 - fastmcp 4 adopted (owner decision), sampling judge backend removed

- Decision (owner). fastmcp 4 is adopted. Tool `title`s appearing, tool-definition changes that
  keep the tools usable another way, a different set of declared capabilities, different
  responses to malformed methods, and a newer SDK are all acceptable. Dependabot PR #53 was
  closed with "ignore this major version" (that only silences dependabot); this is the normal PR.
- Pin. `requirements.txt`: `fastmcp>=4.0.9,<5.0` (was `>=3.4.7,<4.0`). The `mcp` SDK is not
  pinned anywhere; it arrives transitively (1.30.0 -> 2.3.0, plus new `mcp-types`, `httpx2`,
  `httpcore2`, `truststore`). No other file pins fastmcp (CI installs `requirements.txt`).
- Side by side, 3.4.8 vs 4.0.11 (+ mcp 1.30.0 vs 2.3.0), measured earlier on two venvs:

  | Item | 3.x | 4.x |
  |---|---|---|
  | Tool names / descriptions / input schemas (187 direct, 76 gateway) | same | same |
  | Handshake, `Mcp-Session-Id`, unlock gate (IP / session), error texts | same | same |
  | Tool `title` | absent | present on every tool |
  | `survey_worktrees` outputSchema | `{result: array}` (wrapped) | none |
  | Server capabilities `experimental`, `extensions[io.modelcontextprotocol/ui]` | declared | not declared |
  | Unknown JSON-RPC method | -32602 | -32601 |
  | `Context.sample` | present | removed |
  | Client-side attribute names (`inputSchema` ...) | camelCase | snake_case (camelCase deprecated) |

- Checked on 4.0.11 (this PR): `get_access_token` (tools/folder_policy.py, read only) returns the
  verified token and `client_id` over real streamable HTTP with `StaticTokenVerifier`, and a
  wrong token is rejected; `get_context().session_id` still gives a session fingerprint
  (tools/tool_ledger.py); `get_http_request` is unchanged (security tests); `read_image` still
  returns an `ImageContent` (image/png) through `fastmcp.utilities.types.Image`; no non-test code
  reads camelCase MCP attributes or an outputSchema. Minimum `4.0.9` installs and imports.
- Capabilities, plainly. `experimental: {}` was an empty placeholder. `extensions
  io.modelcontextprotocol/ui` is the MCP Apps extension: a server that offers `ui://` resources
  (or `_meta.ui` on tools) can have a host render interactive UI. This repository serves none
  (no `ui://` resource, no `_meta.ui`; the only resources are `companion://...` data), and no code
  or doc depends on the declaration, so dropping it removes a promise nothing was keeping.
  Whether Microsoft 365 Copilot / Copilot Studio render MCP Apps was not verifiable here; with no
  UI resources on offer it makes no difference to either.
- `survey_worktrees`. Still works through the 4.x server: the result arrives as one text content
  block holding the same JSON list of per-worktree dicts. `structuredContent` is no longer
  produced (it was `{result: [...]}`); nothing in relay/socket_tools.py, bench or scripts reads it.
  The tool is normally reached through the `call_tool` gateway, which returns text either way.
- Migration. `tools/judge_backend.py`: the sampling backend (`sampling_judge`,
  `sampling_judge_async`, `sampling_supported`, `_text_of`) is deleted. Production never ran it
  (the client never declares sampling; `MCP_JUDGE_MODE=shadow`, `MCP_JUDGE_BACKEND=sampling`).
  `MCP_JUDGE_BACKEND=sampling` now behaves as `none` (REQUIRE_HUMAN, recorded in shadow) and
  logs one warning plus one `judge_backend_sampling_removed` mechanism row per process;
  `availability()` reports `sampling_backend_removed` instead of `client_sampling`. Bridge and none
  paths and elicitation (`ask_human`) are untouched. Tests: `tools/test_judge_backend.py` (the two
  "Context.sample exists" tests replaced by "the sampling backend is gone" and "a configured
  sampling degrades safely, once"), `tools/test_judge_live_roundtrip.py` (now the elicitation
  round trip only). The `sampling_judge_async` rows are removed from the unreached BASELINE/REASONS and the burndown
  doc; the immutable freeze file keeps its old name (its test pins 77 entries).
- Found by running the judge tests on 4.x (not by the earlier comparison). (1) `ctx.elicit(...,
  response_type=None)` now raises TypeError; `ask_human` swallowed it and would have answered
  "nobody could be asked" forever. It now asks a `bool` confirmation (an accepted False reads as
  a refusal; `_approval_of`). (2) The 4.x client negotiates the 2026-07-28 era by default, where a
  server cannot push an elicitation mid-call (`ctx.elicit` raises); `ask_human` reads that as
  None (not an approval), pinned by a test; the round-trip tests pin `mode="legacy"`. Production
  never reached elicitation (its client declares none), so behaviour there is unchanged.
- Upgrade note. An in-place upgrade of an existing venv moves files between distributions
  (mcp / mcp-types, fastmcp / fastmcp-slim); scripts/bootstrap.py already repairs RECORD gaps
  after the install.
- Open. Not exercised against the live Copilot Studio client.
