# 銅箔 保証期限超過 調査 Skill

## 目的
銅箔の資材略称を1つ受け取り、
1. その銅箔のロットが**保証期限を過ぎてから製品に使われていないか**を洗い出し、
2. **超過がいちばん大きかったロット**について、同じ製品品名の前後のロットと並べた
   **特性ごとの散布図**を出す。

2 が本体である。1 だけなら既存の Excel マクロ（`ExcelSQL/期限切れ材料調査ツール.xlsm`）で
足りる。前後の実績の中でその1点がどこに来るかを見て初めて、「期限を過ぎて使ったが
特性は落ちていない」といった判断ができる。

## 入力
- 資材略称 1つ。`V_銅箔検査結果.資材略称` の表記に合わせる（例 `MT18EX5 RM`、
  `MT18EX(P2)2 RM`）。製品側の `V_製品検査データ.銅箔` は `12D` `35D` のような
  **型式コードで別体系**なので、そちらの値を渡しても当たらない。
- 任意で検査開始日（既定 `2020-01-01`）。

## 実行方法（厳守）
これ1本で、洗い出しから散布図・Excel ブックまで全部出る。`charts.py` と `workbook.py`
は `survey.py` が中から呼ぶので、別に叩かない。

```
python <このSkillのフォルダ>/scripts/survey.py "<資材略称>" [検査開始日] [出力先]
```

- **作業ディレクトリを `scripts/` にすること。** `survey.py` は同じフォルダの
  `charts` / `workbook` を import する。別の場所から実行すると import に失敗する。
- 引数は資材略称だけでよい。検査開始日の既定は `2020-01-01`。
- 出力先の既定は `<ユーザーのホーム>/Desktop/銅箔調査/`。
- 1〜2分かかる。タイムアウトは長めに取る（既定のままだと途中で切られる）。
- 実行系のツールなので unlock が要る。読み取り専用の照会しかしない。

SQL を自分で書き直さない。下の「踏んではいけない穴」は全て実測で確かめた結果で、
どれか1つでも外すと、返らないか、静かに誤った値が出る。

## 出力（既定の出力先に一式）
- `<資材略称>銅箔調査.xlsx` … **これが成果物**。「調査結果」シート（超過ロット一覧）と
  `Sheet1`（散布図の元データ＋グラフ6枚）。グラフは 7.6 × 6.5 cm、既存の調査ブックに合わせている。
- `銅箔調査.json` … 全行と集計
- `銅箔調査.md` … 最大超過・分布・上位30件
- `銅箔調査.png` … 超過日数の分布
- `散布図_*.png` … 特性ごとに1枚（引きはがし4種・絶縁抵抗2種）

## 報告のしかた
数えたり比べたりした結果は、スクリプトが出した `銅箔調査.json` / `銅箔調査.md` の値を
そのまま使う。一覧を目で数え直さない。少なくとも、超過ロットの件数・いちばん超過が
大きいロットの製品ロット番号・その超過日数・出力先を伝える。

## 踏んではいけない穴（全て実測で確認済み）

### 経路
| やってはいけない | 正しい | 理由 |
|---|---|---|
| `V_SPC_LOT_TRACE` で辿る | `TRC_MCL_PRESSvsDOHAKU` と `SCM_DAT_RST_SHIKOMI_DTL_RAI` を `WITH(NOLOCK)` | ビューが重く15分でも返らない |
| `V_銅箔検査結果.製品ロット` で結合 | 上記2テーブル経由 | この列は常に空。旧版はこれで**常に0件**だった |
| `V_製品検査データ` を製造品名で走査 | `SPC_SEI_HIN_JSK` + `SPC_SEI_KENSA_KEKKA` | 100秒 → 0.2秒 |

### SQL の書き方
- **テーブル変数（`@CF`）を使わない。** 統計を持たず1行と見積もられ、66,583行側に
  最悪の計画が選ばれる。`#temp` + インデックスにすると 53.6秒 → 22.2秒。
- **結合条件に `OR` を書かない。** `= full OR = base` は seek できない。表裏 × full/base ×
  2テーブルの**8本の等値結合**に分解する。
- **`COLLATE DATABASE_DEFAULT` を必ず付ける。** テンポラリ表は tempdb の既定照合順序に
  なり、実テーブル（`Japanese_CS_AS_KS_WS`）と等値比較した瞬間に落ちる。
- **1バッチで実行する。** `#temp` の寿命は文をまたぐと切れる。
- SPC 側は `TOP N` + `ORDER BY SEIZO_DT DESC` + `WITH(INDEX(IX_SPC_SEI_KENSA_KEKKA))`。
  結合キーは `HINME` + `LOT_NO` + `LOT_Y` の**3列複合**。ロット番号だけでは一意にならない。

### 値の意味
- **試験値の負値は測定値ではなくコード。** `> -100` のものだけ採用する。素通しすると
  剥離強度に `-200` や `-777777` が混ざって平均も散布図も壊れる。
- **はんだ耐熱性は値そのものが判定。** `-777777`→不合格 / `-300`→合格 / `-299`→不合格? /
  それ以外→要確認。
- **規格値の `-200` `-300` はコード。** 上限が `9999999` 以上なら「上限なし」。
- はんだ耐熱の項目名は温度条件が後続するので**前方一致**で拾う。

### 絞り込み
- `製造年月日 <= 検査年月日 + 36か月`。無いと無関係な遠い製造ロットが混ざる。
- `保証期限 >= 検査年月日`。**保証期限が検査年月日より前という壊れた行が実在する**
  （両系統に存在、2026-06-09 確認）。

## 散布図の作り（既存の調査結果ブックに合わせる）
`調査結果/*.xlsx` の Sheet1 と chart1〜12 がお手本。
- **特性ごとに1枚。** 1枚に複数特性を重ねない。
- X は通し番号、範囲は `0 〜 点数+1`（両端に余白）。Y は自動調整（特性ごとに範囲が違う）。
- **対象＝期限超過がいちばん大きいロット**。四角・大きめの別系列にする。
- 母集団は**対象を挟んだ前後**。前半分・後半分を狙い、片側が足りなければもう片側から
  埋める。期間指定はしない。最大50件、取れなければあるだけでよい。
- 対象が端に来ることも、対象の測定値が空のこともある（`3EC-VLP-18RM` に実例）。
  測定値が無いときは点を消さず、位置を破線で残す。
- 絶縁抵抗は 10^9〜10^15 と桁が広いので**対数軸**。
- 点数を凡例に出す。5点と50点が同じ見た目だと1点の重みを誤読する。

## 速度
`V_銅箔検査結果` の走査だけが重い（22〜54秒）。材料ごとに1回引いて
`~/.companion_cache/copper-foil-survey/cf_*.json` に持ち、以降は `#CF` へ VALUES で
流し込む。既存VBAが Excel シートにキャッシュしているのと同じ設計。キャッシュは
要求された開始日を含んでいるときだけ使う。

キャッシュも成果物も、この Skill のフォルダの**外**に置く。中に置いていた頃は、
実行するたびにフォルダの中身が変わり、そのハッシュで判定している信頼が毎回外れて、
一度承認しても次の実行で使えなくなった。

## 権限
`.env` の **readonly** アカウント。読み取り専用の照会のみで、DDL/DML は実行しない。
`.env` の場所は環境変数 `COPPER_FOIL_ENV` で差し替えられる。
